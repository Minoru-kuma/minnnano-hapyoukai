# MVP UI設計

この文書は今後実装する画面の設計。確認時点の画面コードは `MainActivity` の初期 Greeting のみであり、以下の画面・操作は未実装。

## 実装順と画面遷移

Room基盤の後、下表の順に操作可能な範囲を広げる。未実装の操作は画面に出さない。

| 段階 | 画面・遷移 | 主な操作 |
| --- | --- | --- |
| 1. 発表会 | 発表会一覧 → 発表会詳細／新規・編集 | 発表会の追加、確認、編集、削除 |
| 2. 部 | 発表会詳細 → 部の内容／部の新規・編集 | 任意名の部を追加、編集、削除 |
| 3. 出演者・演奏 | 部の内容 → 演奏の新規・編集 → 出演者選択 → 出演者の新規・編集 | 生徒・講師を登録し、1つの演奏に複数人を参加させる |
| 4. 曲 | 演奏の新規・編集 → 曲の新規・編集 | 1つの演奏に複数曲を追加、編集、削除 |
| 5. 作曲家表記 | 曲の新規・編集 → 作曲家候補・表記選択 | 作曲家とプログラム上の表記を個別に指定 |
| 6. 順序 | 発表会詳細／部の内容／演奏の編集 | 部・演奏・曲を上下ボタンで並べ替え |
| 7. プレビュー | 発表会詳細 → プログラムを見る | 全部または選んだ部を読み取り専用で表示 |

発表会一覧を起点にし、上部に画面名と「戻る」、各一覧に「発表会を追加」「部を追加」「演奏を追加」など対象を明示した主操作を置く。削除は編集画面の補助操作に置く。出演者一覧は発表会一覧の「出演者」からも開ける共通画面とし、選択目的で開いた場合のみ選択状態と「この出演者で決定」を表示する。

## 入力と一覧表示

| 対象 | 必須入力 | 任意入力・表示 |
| --- | --- | --- |
| 発表会 | 発表会名 | 開催日、会場。詳細には部の一覧を表示 |
| 部 | 部の名前 | 自由入力。固定の候補や部数上限を設けない |
| 出演者 | 名前、区分（「生徒」「講師」） | 生徒のみ学年を任意入力。区分は明示的に選択 |
| 演奏 | 出演者1人以上 | 出演者一覧と曲一覧。曲は未登録でも保存可能 |
| 曲 | 曲名 | 「作曲家の表記」、作曲家候補との関連付け |

必須ラベルに「必須」を付け、空白のみの値を許可しない。エラーは入力欄の直下に日本語で表示し、保存操作時は最初のエラー欄へ移動する。作曲家表記は空欄も許可し、勝手に「不明」などを補完しない。表記の空白・全半角・略称は自動で統一しない。

発表会一覧は名称・日付、部の一覧は名称・演奏数、演奏一覧は番号・出演者名・曲名を表示する。複数人・複数曲を省略する場合は「ほか2人」「ほか1曲」を添え、詳細で全件を読めるようにする。学年は値がある生徒だけに表示する。同姓同名の出演者を名前だけで同一人物と判断しない。

## 複数出演者と複数曲

- 演奏編集画面の「出演者を追加」で既存の出演者を複数選択できる。同じ演奏に同一人物を重複追加しない。「参加を外す」は演奏からの解除だけを行い、出演者本人の登録を削除しない。
- 講師2人を選べば講師連弾として扱える。生徒と講師の連弾も同じ画面で登録する。演奏を1人専用の入力欄で表現しない。
- 講師のみの演奏を新規追加するときは部の末尾、生徒を含む演奏は講師のみの演奏の前を初期位置とする。この区分は出演者から判断し、独奏・連弾別のモデルは増やさない。
- 一度保存した演奏の順番は、出演者の変更だけでは動かさない。利用者が「上へ」「下へ」を押したときに変更する。講師演奏を途中に置くことも許可する。
- 「曲を追加」で複数曲を登録し、演奏編集画面で順に並べる。曲の編集画面は「反映して戻る」で演奏の編集中データへ反映し、演奏画面の「保存」で出演者・曲をまとめて保存する。
- 曲がまだない演奏は「曲が未登録」と表示し、入力途中の状態として保持する。プレビューにも同じ表示を出し、黙って欠落させない。

## 作曲家とプログラム表記

曲の「作曲家の表記」は自由入力でき、その曲に保存した文字列をプログラムにも使用する。同一作曲家でも曲ごとに異なる表記を許可する。

入力に応じて端末内の作曲家・別表記から候補を表示する。候補の選択では次の操作を区別する。

1. 「この作曲家に関連付ける」：作曲家のみ関連付け、入力済み表記は維持する。
2. 「この表記を使う」：選んだ候補の表記へ入力欄を変更する。置き換わる文字列をボタンと同じ画面で示す。

たとえば「J.S.Bach」を入力して「バッハ」の作曲家候補に関連付けても、保存される表記は「J.S.Bach」のまま。作曲家が見つからなくても入力した表記だけで保存できる。別表記を候補へ登録する場合は「この表記を候補に追加」の明示操作とする。作曲家側の名称や別表記を後で変更しても、保存済みの曲の表記は書き換えない。

作曲家管理の詳細画面や講師別の表記設定は後続で検討し、MVPでは曲入力からの選択・追加を優先する。

## 順序とプレビュー

部・演奏・曲はそれぞれの一覧で「上へ」「下へ」を提供し、端の移動ボタンは無効にする。スクリーンリーダー向けのラベルには対象名を含める。高度なドラッグ操作は導入しない。出演者は選択した順に表示し、並びを変更する場合は演奏編集画面で同じ上下操作を使う。

プレビューは発表会名、日付・会場（入力時）、部名、演奏番号、出演者、曲名・その曲の作曲家表記を縦に表示する。演奏番号は各部で1から振り直し、曲が複数あっても演奏番号は1つ。講師連弾では全員を表示する。小さな画面でも横スクロールを必要としない。編集に戻った後も表示順と表記を保持する。PDF、共有、印刷は今回の範囲外。

## 保存・戻る・削除

- 編集画面の主操作は「保存」。保存中は進行状態を示し、二重保存を防ぐ。成功後に前画面へ戻り、更新された一覧を表示する。永続化の成功前に入力欄を消さない。
- 入力内容が変わった状態で戻る場合は「変更を破棄しますか」と「編集を続ける」「破棄」を表示する。曲の編集中データも演奏全体の未保存変更として扱う。
- 発表会・部の削除では対象名、削除される部／演奏／曲の件数と「元に戻せません」を確認画面に表示する。「キャンセル」を既定の選択とする。発表会・部を削除しても共通の出演者・作曲家の登録は残す。
- 演奏の削除では参加情報と曲が削除されること、出演者本人の登録は残ることを明示する。編集中の曲を削除する場合も対象曲名を示して確認し、演奏を保存した時点で確定する。
- 他の演奏で使用中の出演者は削除を拒否し、「演奏に登録されています。参加を外してから削除してください」と対象の発表会・部を示す。使用中の作曲家はMVPで削除操作を提供しない。

## 空・読み込み・エラー状態

| 状態 | 表示と回復操作 |
| --- | --- |
| 発表会なし | 「発表会を登録しましょう」＋「発表会を追加」 |
| 部なし | 「部がありません」＋「部を追加」 |
| 演奏なし | 「演奏がありません」＋「演奏を追加」 |
| 出演者の検索結果なし | 「該当する出演者がいません」＋「出演者を新規登録」 |
| 読み込み中 | 進行表示。空一覧の案内は読み込み完了まで出さない |
| 読み込み失敗 | 「読み込めませんでした」＋「もう一度試す」 |
| 保存失敗 | 入力内容を保持し「保存できませんでした。もう一度お試しください」＋再保存 |
| 対象が既に削除された | 「この項目は削除されています」＋親一覧へ戻る操作 |

通信を前提とした文言や再ログインは不要。エラーに生徒名、SQL、スタックトレースなどの内部情報を表示しない。

## スマートフォンでの操作性と実装境界

主要な本文は16spを目安にし、タップ領域は48dp以上を確保する。文字拡大時は折り返しと縦スクロールで対応する。アイコンだけの操作には読み上げラベルを付け、色だけで生徒・講師、エラーや選択状態を区別しない。キーボードとシステムバーに保存ボタンや入力欄が隠れないよう余白を調整する。

既存のCompose・Material 3テーマを使用し、画面状態はViewModel、データはRepository経由でRoomから取得する。依存関係は手動で渡す。画面遷移にはNavigation Composeを必要になる段階で追加し、個人情報を経路文字列に含めずIDで対象を渡す。回転時は編集中の内容を維持し、プロセス終了後も編集中データを復元する範囲は画面実装時に確認する。

個人情報は端末内で扱い、ネットワーク、外部分析、リモートログを導入しない。例示・プレビュー・テストには架空データだけを使う。実装時は小型画面、文字拡大、TalkBack、講師連弾、複数曲、入力した作曲家表記の保持、削除の影響範囲を確認する。
