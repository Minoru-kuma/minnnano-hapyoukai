# Room 基盤の設計

端末内保存の基盤は、発表会・部・出演者などの入力画面とプログラムのプレビューから Repository 経由で利用する。Room の初期スキーマを version 1 とし、既存の Android / Kotlin / Compose 設定を維持する。

## データの関係

| エンティティ | 役割 | 関係・順序 |
| --- | --- | --- |
| Recital | 発表会 | 任意の数の Section を持つ |
| Section | 利用者が命名する部 | Recital に所属し、発表会内の表示順を保持 |
| Performer | 生徒または講師 | STUDENT / TEACHER を区別し、必要に応じて学年を保持 |
| Performance | ひとつの演奏枠 | Section に所属し、演奏順を保持 |
| PerformanceMember | 演奏枠への出演者の参加 | Performance と Performer を結び、出演者の掲載順を保持 |
| Piece | 演奏枠内の曲 | Performance に所属し、曲順とその曲の作曲者表記を保持 |
| Composer | 作曲者の同一性 | 曲ごとの掲載表記とは独立した識別子を持つ |
| ComposerAlias | 作曲者の表記候補 | Composer に所属する複数の表記を保持 |

PerformanceMember により講師の連弾や生徒と講師の共演を表現し、Performance に単一の performerId を置かない。ひとつの演奏枠に複数の Piece を保存できる。Section の名前や個数に固定の選択肢を設けない。

## 整合性と削除

- 発表会、部、演奏枠の削除は所有する子を CASCADE で削除する。
- 使用中の Performer の削除は RESTRICT とする。削除によって演奏枠から出演者が黙って消えることを防ぐ。
- Composer の削除では ComposerAlias を CASCADE で削除し、Piece の composerId は SET NULL とする。Piece に保存した掲載用の作曲者表記は残す。
- PerformanceMember は演奏枠と出演者の複合主キーで重複参加を防ぐ。
- 外部キー列に索引を用意する。順序を持つ一覧は displayOrder と識別子で安定して取得する。
- 親レコードの更新に INSERT REPLACE を使用しない。競合時の削除・再挿入で子が消えることを避け、通常の UPDATE を使用する。

演奏枠の作成と出演者の登録、出演者の入れ替えは Repository のトランザクションでまとめる。少なくともひとりの出演者を要求し、同じ出演者の重複を検証する。SQL の外部キーだけでは「出演者がひとり以上」という条件は表せないため、UI からの更新経路は Repository に揃える。

新規演奏枠は出演者と複数曲をまとめて保存できる。既存の演奏枠も `updatePerformanceProgram` により、出演者の選択順と曲の掲載順を一括保存する。演奏枠の既存の順序は保持し、曲は編集済みの一覧で置き換える（曲の ID は再採番）。未登録の出演者・作曲家、重複出演者、不正な曲名などによって失敗した場合は、参加情報・曲の削除も含めてロールバックする。更新対象が削除済みの場合はエラーを返し、保存成功にしない。

画面は `observeProgram(): Flow<ProgramSnapshot>` で全8テーブルの一貫した状態を購読する。Room の全テーブルの変更通知を受け、ひとつの読み取りトランザクションで全一覧を取得する。別々の Flow を合成した場合に起きる、親削除前と子削除後などの異なる時点の混在を防ぐ。小規模 MVP を前提に端末内の全件を取得し、各画面で ID により必要な範囲を選ぶ。

## 演奏順と作曲者表記

新しい演奏枠を追加するとき、講師のみの枠は末尾、生徒を含む枠は既存の講師枠より前を既定とする。既存の演奏枠の編集では掲載順を維持する。高度なドラッグ並べ替えは今回の対象外とする。

部・演奏枠・曲の並べ替え API は同一の親に属する全識別子を重複なく要求し、トランザクションで順序を更新する。別の親の項目を混ぜた並べ替えは受け付けない。削除後の順序値の欠番は許容し、一覧は明示的な表示順で取得する。

Piece の作曲者識別子は未指定を許容する。利用者は作曲者の候補を先に登録せずに曲の掲載表記を入力できる。同じ Composer を参照する曲でも掲載表記はそれぞれ保持し、Composer や ComposerAlias の編集によって過去の入力を自動変更しない。講師別の表記設定を将来追加しても、既存の曲の表記を維持できる構造とする。

## プライバシーと今後の確認

データベースはアプリの端末内領域に保存する。ネットワーク権限、外部 API、遠隔ログ、実在の個人情報を含むサンプルは追加しない。Android の自動バックアップと端末移行も端末外への経路になるため、Manifest と両世代のバックアップ規則で保存領域を除外する。

スキーマの破壊的な再作成による移行は行わない。次回以降のスキーマ変更では明示的なマイグレーションと保存済みデータの維持を検証する。実機またはエミュレーターの Room テストでは、外部キー、親削除、連弾、複数曲、作曲者削除後の表記維持、出演者入れ替え失敗時のロールバックを確認する。
