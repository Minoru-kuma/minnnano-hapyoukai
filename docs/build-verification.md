## Roomテストの対象

`RecitalDatabaseTest` は各テストで `Room.inMemoryDatabaseBuilder` を使用し、架空データだけを登録する。既存の `recitals.db` を開かない。

- 任意名の複数部、講師2人の連弾、複数曲とそれぞれの表示順。
- 使用中の出演者の削除拒否、発表会削除時の子データ削除、共通の出演者・作曲家の保持。
- 作曲家名・別表記の変更と作曲家削除後も、各曲の表記を空白まで保持。
- 生徒を講師演奏の前に置く初期順、手動順と出演者変更後の順序保持。
- 複合追加の途中で曲の外部キー違反が発生したとき、演奏・出演者の参加情報・曲・既存演奏の順序変更をまとめてロールバック。
- 部と曲の並べ替え、別の親に属する項目や重複順序の拒否、空・重複した演奏メンバーの拒否。
